# 身份、权益与付费墙 —— 目标架构

> **这份文档的用法**:第 4 节的**不变量**是全部内容的核心。改动任何与身份/权益/付费
> 相关的代码前,先看它违不违反某条不变量;新增端点前,先看它该不该进第 5 节的闸门矩阵。
>
> **它不是清零重设计**。第 6 节的每条取舍、第 4 节的多条不变量,都是已经踩过坑换来的;
> 忘掉它们重来一遍只会重踩。文档从需求推导,但把教训当硬约束写死。

---

## 1. 需求

GoMuseum 是**现场**使用的 AI 博物馆导览:用户站在作品前,拍照识别,听讲解。

**收费形态**:巴黎 7 日通票 €7.99,覆盖卢浮宫 / 奥赛 / 橘园。不按馆卖。

不按馆的理由:加馆不增 SKU;Play 无原生补差价,自己做差价升级 = 收错钱的风险;
用户心智是"我在巴黎待几天"而不是"我要买哪几个馆"。

**付费墙建在「现场体验」,不建在「内容」**:

| 能力 | 免费 | 通票 |
|---|---|---|
| 浏览 / 搜索 / **完整文字讲解** / 预设问答 | ✅ 无限 | ✅ |
| 拍照识别 | **5 次**(跨馆) | 高额度 |
| 语音讲解 | **1 件**(见 6.4 的精确范围) | 全部 |

为什么切语音而不切内容:①博物馆的真实姿势是边看边听 ②官方语音导览 €5-6 是现成
价格锚点,我们 €7.99 覆盖三馆 ③搜索绕不过语音 ④架构上只需在发音频处加闸,
不碰生成链路。切内容则要造"简短版",成本翻倍、质量闸跑两遍,而截断显示不是
"免费版"是"坏了"。

**注册门槛**:现场掏手机的人不会为了试用去注册。所以**用不需要注册,买需要**。

## 2. 用户类与身份状态机

### 2.1 三种身份

| 身份 | 有无令牌 | 说明 |
|---|---|---|
| **无令牌调用方** | 无 | curl / 老客户端 / 攻击者。只能读公开内容,**任何计费或权益动作一律拒绝** |
| **游客** | 有(`is_guest=true`) | App 启动自动创建。是**真实 User 行**,有 UUID,按 `device_id` 复用 |
| **注册用户** | 有(`is_guest=false`) | email+密码 或 Google。**唯一能购买的身份** |

⚠️ 「游客」不等于「匿名」。游客有账号、有 UUID、有独立权益行 —— 这是免费额度能
跟人走的前提。App 内不存在"未登录"状态。

### 2.2 状态迁移

```
        (首次启动)
             │  device_id
             ▼
      ┌─────────────┐   注册 / Google 登录(带游客令牌)
      │   游客 A    │ ─────────────────────────────────▶ ┌──────────────┐
      │ is_guest=T  │        **就地转正,UUID 不变**        │  注册用户 A   │
      └─────────────┘                                    │ is_guest=F   │
             │                                           └──────────────┘
             │ 换设备 / 清数据                                   │
             ▼                                                  │ 删号
      ┌─────────────┐                                           ▼
      │   游客 B    │  ← 与 A 无关,额度重新计                 (账号消失)
      └─────────────┘                                     权益撤销·订单匿名化
```

**就地转正是硬要求,不是优化。** 若注册时新建一行:新 `user_id` 查不到旧权益 →
已购通票凭空消失;而且**恢复购买也救不回来** —— 发放靠 `store_transaction_id` 幂等,
收据已存在就返回旧记录、不给新用户发权益,接口却仍返回成功(静默丢钱)。

### 2.3 每次迁移必须守恒的东西

| 迁移 | 免费额度 | 通票权益 | 已认领首件 |
|---|---|---|---|
| 游客 → 注册(就地转正) | **保留**(不重发) | **保留** | **保留** |
| 换设备 / 清数据 | 重新计(新身份) | 跟账号走:登录即回来 | 新身份重新计 |
| 删号 | 消失 | **撤销**(revoked) | 消失 |

「换设备后通票跟账号走」正是**买票必须登录**的理由:游客身份绑设备,游客买了票
换手机就永久拿不回。

## 3. 权益状态机

```
  not_purchased
       │ 商店凭证校验通过
       ▼
  purchased_not_activated ──── 用户显式确认 ────▶ active ──到期──▶ expired
       │                                            │
       └──────────── 退款 / 删号 ────────────────────┴──▶ revoked
```

| 状态 | 含义 | 能用高级功能? |
|---|---|---|
| `not_purchased` | 没买 | ❌(只有免费层) |
| `purchased_not_activated` | 买了,**未开始计时** | ❌ —— 但**绝不该给他看购买页**,该弹激活确认 |
| `active` | 生效中 | ✅ |
| `expired` | 到期 | ❌(回落免费层,但免费首件已用掉就没了) |
| `revoked` | 退款 / 删号撤销 | ❌ |

**为什么要 `purchased_not_activated`**:旅游产品的用户常提前几天买。购买即计时会
白烧有效期,是差评来源。

**它的代价**:必须有一个明确的**激活触发器**。设计了这个状态却不实现触发器,
后果是权益永远停在 `purchased_not_activated`、`can` 恒为 false ——
**用户付了钱,拿到的和没付一样**。这是本项目真实发生过的事故。

**激活规则**:首次使用高级功能时弹确认框,用户点"现在开始"才 `activate`。
绝不静默激活(误触一次烧掉整张票);绝不购买即激活(白烧提前购买的天数)。
`activate` 幂等:再调不续期也不重置。

**到期判定在读取时实时计算**,不依赖任何定时任务把 status 刷成 expired ——
定时任务漏跑就是白送权限。

## 4. 不变量(核心)

每条都可检验。违反其一即为缺陷,不论代码看起来多合理。

### 身份

- **I1 · `user_id` 只来自令牌。** 永不来自查询参数、请求体或客户端任何输入。
  *违反的后果(真实发生过两次)*:①`user_id` 当查询参数 → 任何人可读他人权益、
  可 `POST /activate` 烧掉别人的 7 天票;②购买时取 `request.user_id or device_id`,
  而前端传 null → 权益的 `user_id` 存成设备号字符串,而查询按 UUID → **票落库了,
  用户自己看不到**。

- **I2 · 身份迁移守恒。** 见 2.3 表。转正不重发额度、不丢权益、不清首件。

### 闸门

- **I3 · 每条产音频或产识别的路径都必须自己过闸。** 客户端的检查只为省一次往返;
  老 App / curl / 改客户端都能绕过前端。**唯一执行点在服务端。**

- **I4 · 内容端点不得下发音频直链。** 内容端点无鉴权(文字免费是既定策略),
  发直链等于拆掉付费墙 —— 音频 key 做成不可推测也白搭,是我们自己发出去的。
  只给 `has_audio` 布尔。

- **I5 · 闸门必须跑在花钱动作之前。** TTS / GPT 调用之前拦,拦晚了钱已经花掉。

- **I6 · 权益判定无副作用;认领只在交付成功之后。** 闸跑在生成之前,而生成可能
  404(该语言无正文)/409/503。在判定时认领 = 用户什么都没听到、免费名额却没了。

- **I7 · 拦截必须伴随状态推进。** 只拦不认领的话,判定会永远返回"可认领",
  免费用户可以无限使用 —— 闸等于没加。

### 钱

- **I8 · 购买必须由**商店**凭证证明。** 没有凭证校验能力(未配置/API 不可达)时
  **拒绝购买**,绝不"当作有效"。*违反的后果*:曾经的 mock 校验对任何 token 返回
  valid=true,任何登录用户编造一个字符串就能白拿 €7.99。

- **I9 · 幂等键必须来自商店(Play 的 `orderId`)。** 绝不回退到客户端提供的
  `receipt_data` —— 那样改一个字符就能再拿一张票。

- **I10 · 退款必须连权益一起撤。** 只标订单退款、留着权益生效 = 退了钱还能用满 7 天。

- **I11 · 买票必须登录。** 游客身份绑设备,游客买了票换手机就永久拿不回。
  服务端拦(403),不能只靠 UI 隐藏按钮。

### 工程纪律

- **I12 · 前端不得自行组合权益布尔值。** 只读服务端下发的 `can`。多端各写一套
  必然不一致(过期没关、退款没撤、恢复购买状态错位)。

- **I13 · 契约不得暴露不存在的能力。** 功能停用时,对应的 `can` 字段一并移除。

- **I14 · 埋点失败绝不影响业务事务。** 不得回滚调用方尚未提交的数据。
  *违反的后果*:埋点写失败把刚建的 `UserBenefits` 一起回滚 → 同设备第二次登录
  又建新账号 → 防刷额度失效。

- **I15 · 失败关闭。** 凭证缺失、配置缺失、下游不可达 → 拒绝,不放行。
  唯一例外:**免费层的可用性**(权益读取失败时按免费层展示,不假装有通票,
  也不把免费用户挡在门外)。

- **I16 · 每个服务层函数必须有调用方。** 写完不算完,接上才算完。
  *本项目已四次踩此坑*:`log_event`、`/activate`、`revoke_for_purchase`、
  真实收据校验 —— 全都建好了、从没接。**新增服务层函数时必须能回答"谁调它"。**

## 5. 端点闸门矩阵

新增任何端点时,先问它属于哪一行。

| 端点 | 鉴权 | 闸 | 备注 |
|---|---|---|---|
| `GET /museums`、`/{slug}`、`/{slug}/objects` | 不需要 | 无 | 浏览永久免费 |
| `GET /{slug}/objects/{qid}/content` | 不需要 | 无 | 文字免费。**⛔ 不得含 `audio_url`**(I4) |
| `GET /search`、`/{slug}/search` | 不需要 | 无 | 搜索永久免费 |
| `POST /recognize`、`/{slug}/recognize` | 令牌或 device_id | **额度** | 命中扣 1;未识别与缓存命中不扣 |
| `GET /{slug}/objects/{qid}/audio` | **必需** | **权益** | 402 `pass_required` |
| `GET .../audio/stream` | **必需** | **权益** | ⚠️ 播放器直取、不经 HTTP 拦截器,客户端须自带令牌 |
| `POST /content/tts/generate` | **必需** | **权益** | 有 qid 按作品判;无 qid(任意文本)需通票生效 |
| `POST /payment/verify` | **必需** | **非游客**(I11) | 身份取自令牌(I1) |
| `POST /payment/rtdn` | 共享密钥 | — | 退款回调。始终返 204,否则 Pub/Sub 无限重投 |
| `GET/POST /entitlements/*` | **必需** | — | 身份取自令牌(I1) |

## 6. 已知取舍(明确接受,不是没看见)

### 6.1 `device_id` 由客户端提供 → 免费额度可刷

换一个 `device_id` 就能再拿一份免费额度(受游客登录 5次/小时 限流约束)。

**不做 IP 封堵。** 博物馆是共享 WiFi/NAT,一个出口 IP 后面几十上百个真实游客,
按 IP 限流会把真用户挡在门外,代价远大于挡住的滥用。

**现在做的**:记录 `guest_created` 事件,滥用的形态是"短时间大量新游客",
靠 `ops_report` 看得见。**根治**:Play Integrity 设备证明,等有真实滥用证据再上。

### 6.2 删号重注册可重置免费额度

与 6.1 同源。新账号 = 新额度是账号系统的自然语义。接受。

### 6.3 音频 URL 不可推测,但可转发

拿到 URL 的人可以把它发给别人。彻底方案是私有桶 + 短时签名 URL,需要在
Cloudflare 建桶。付费规模起来再上。

### 6.4 免费语音的精确范围 = **一件作品 × 一种语言 × 主讲解段**

不能只按作品判:一件作品有多个段落(主讲解/背景/分析/问答/作者介绍),每段独立
TTS,再乘 10 种语言 —— 「免费一件」实际会是几十次生成。

代价:用户切换界面语言后,免费试听不再覆盖新语言。可接受(试听已经发生过)。

### 6.5 免费额度耗尽后不恢复

不做"每日重置"。通票是时长制,免费层是一次性体验额度。

## 7. 怎么保证不变量不被悄悄破坏

这一节针对本项目的真实失效模式:**设计没问题,接线缺失**。

今天为止发现的严重问题里,没有一个是设计错误 —— 全是"写了没接"或"两个正确模块
之间的缝"。所以防线不能只靠设计评审(它对这类问题基本无能为力),必须机械化:

1. **零调用方检测**(对应 I16)。服务层里没有任何调用方的函数,要么接上,
   要么明确标注为对外 API 的一部分。
2. **端到端钱路径测试跑真实环境**。内存 sqlite 跑不出真问题 —— 本轮
   「免费名额被无音频的作品烧掉」「内容接口泄漏直链」都是在 staging 真跑才暴露的。
   路径:游客 → 免费试听 → 撞墙 → 登录 → 购买 → 激活 → 到期 → 退款撤销。
3. **闸门接线测试**(对应 I3)。单元测试常把闸 mock 掉,必须另有一条测试确认
   端点**真的**挂着闸,否则重构悄悄摘掉不会变红。
4. **契约回写**。每个特性完成后判断是否影响本文档;影响则同步更新。
