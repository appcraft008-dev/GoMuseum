# 方案 A:懒生成防刷 设计

日期:2026-10-11 · 分支 `feature/lazy-gen-abuse-guard` · 状态:范围已获用户确认(10-11),待写实施计划
姊妹方案:[方案 B 无图作品不对用户开放](2026-10-11-hide-imageless-objects-design.md)(独立分支、在 A 之后做)

## 一、起因

10-10 #877 把懒生成全站日上限从 300 段提到 1000 段(10-07/10-08 只靠运营者逛馆就顶满 301/315 段)。
用户问:这会不会让"爬虫雪崩"风险变高?

查证结论:
- **普通爬虫点不着**:内容端点只有带有效令牌才点火(`museums.py:139` `_caller_id`)。
- **脚本能点着**:游客令牌谁都能领;换 device_id 就是新游客号;游客号创建限流 5 次/小时/IP
  → 单 IP 一天 120 个号。
- **不会雪崩,但会变贵**:全站上限是硬顶,到线全站停到 UTC 零点。300→1000 让最坏一天从约 $1–3 变成
  约 $4–10、冷门件永久入库从约 36 件变成约 120 件;并且一个脚本就能把当天额度吃光,
  让所有真实用户看到「明天再来」。
- 全站上限是钱包止损,不分是谁 —— 缺的是"按人""按 IP"两道。

## 二、方案:三层上限

点火(拿到锁、真正调度后台任务)前依次检查,任一层满了就不点火,返回 `unavailable_reason="daily_cap"`
(10-10 已有的加法字段,App 已会显示「明天再来」,**不改契约、不发包**)。

| 层 | 新/旧 | 默认值 | 挡什么 |
|---|---|---|---|
| ① 每账号每日点火次数 | 新 | 正式账号 40、游客 15;`can_preview` 运营账号不限 | 单个脚本账号 |
| ② 每 IP 每日点火次数 | 新 | 100 | 单 IP 换 device_id 开游客号 |
| ③ 全站每日段数 | 旧 | 1000 段(不改) | 多 IP 分布式;最后的钱包止损 |

**点火一次** = 开始一次懒生成 / 一次懒翻译(各算 1)。不算的:打开已有内容的件;别人正在生成的件
(没拿到锁);生成完后再打开。生成失败退回 stub、下次打开重新生成会再算一次(罕见,接受)。

**默认值依据**:运营者一人逛馆一天约 36–38 件触发,且有 `can_preview` 豁免;真实游客一天打开的未生成件远少于此。
IP 100:博物馆共享 WiFi 下同馆多人同日各开几件未生成件,到不了 100。数值放常量,看 WARNING 日志再调。

## 三、实现要点

- **计数存 Redis**:`INCR lazy:u:{user_id}:{UTC日期}`、`lazy:ip:{ip}:{UTC日期}`,首次 `EXPIRE` 2 天。不建表、不加字段。
  复用 `recognition/service.py:_get_redis`(已有连接失败冷却,不会每次请求等超时)。
- **先查后计**:检查 ①② 未满 → 拿锁成功 → 才 `INCR`。拿锁失败不计。
- **Redis 不可用 → 放行 + ERROR 日志**(fail open)。第 ③ 层在 DB,照样兜底;fail closed 会让 Redis 一抖全站懒生成停摆。
- **IP 来源**:端点加 `request: Request`,取 `request.client.host`。已在 prod 核过 uvicorn 拿到的是真实客户端 IP
  (日志里 90.160.x / 84.123.x 等),不是网关地址。
- **身份信息**:`_caller_id` 现在只返回 user_id;需要同时拿到 `is_guest` / `can_preview` → 让 `maybe_trigger`
  接收 user 对象(或这两个布尔),不在 lazy 里再查一遍用户。
- **被拦记 WARNING**:`lazy: per-user|per-ip cap hit user=… ip=… count=…`,留作以后判断有没有人在刷的证据。
- 只改 `services/enrichment/lazy.py` 和 `api/v1/endpoints/museums.py`(content 端点)。

## 四、写入面

只新增 Redis 计数键(2 天过期)。不写 DB、不碰内容与音频。

## 五、测试

- ①②③ 各自到线被拦,返回 `daily_cap`;未到线正常点火。
- `can_preview` 不受 ① 限制(仍受 ②③)。
- 游客 15、正式 40 两档。
- 没拿到锁(已在生成)不计数。
- Redis 抛异常 → 放行,第 ③ 层仍生效。
- 不同 UTC 日期用不同键。
- 匿名(无令牌)仍然不点火、不计数(回归)。

## 六、不做

- 不改全站 1000 段;不做 Play Integrity 设备证明(等真实滥用证据);不改游客号创建限流。
