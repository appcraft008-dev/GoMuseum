# 必看打卡 设计(2026-10-27)

## 一、为什么做

每个馆后端已有一份官方必看清单(`museums.yaml` 的 `must_see:`),但只用来把这些作品排到馆藏列表最前,App 里看不出来。游客进一个上万件藏品的馆,不知道先看什么;我们也少了一个"逛的过程中有乐趣、逛完有纪念"的东西。

做法:每个馆加一个「必看」页,列出官方必看作品;游客在馆里**拍照认出一件就打卡一件**,打满一轮给一枚带日期的勋章,勋章永久保留。

定位是**逛的过程中收集的乐趣**,不是行前规划路线;能从官网取到展厅号的馆,顺带告诉游客去哪个厅找。

## 二、用户已定的(10-27 讨论)

1. 每个有必看清单的馆,馆页顶层新增「必看」标签页,**进馆默认打开它**;没有清单的馆不显示这个标签页,默认仍是「藏品」。
2. **只有现场拍照识别成功才算打卡**,相册上传不算。点清单里的作品进讲解页不算。
3. 打卡**不免费**:照常走识别的扣费(免费额度/通票),不为打卡开例外。
4. **以前的识别记录不算**,从新版本起计数(老记录分不清拍照还是相册)。
5. **删足迹,对应的打卡跟着消失**。
6. **按轮计**:在这个馆距上一次打卡超过 **30 天**,下次打卡开新一轮,进度从 0 开始。
7. **打满一轮 = 一枚勋章**,永久保留,带完成日期(如「2026-10 · 卢浮宫 12/12」)。勋章只是个人纪念:不排名、不换积分、不和别人比。(这修订了 9-30「不做徽章」的决定,用户 10-27 同意。)
8. **清单里现场拍不到的件**(10-27 定):
   - 上线前逐件检查每馆必看作品能否被识别(库里有可比对的参考图/向量);认不出的先从清单拿掉或补参考图。
   - **不监测「在不在展」**:人工核对不可行(只有一个人),用户反馈分不清「没找到」和「不在展」,官网数据不是每个馆都有(10-27 实查:卢浮宫官方 JSON 有展厅、橘园/小皇宫(巴黎博物馆集团藏品库)网页有展厅、奥赛官网 403 拒绝程序访问),以后的馆更无法保证。
   - 改为**选清单时就避开**:必看只放「常年在展的镇馆之宝」,上新馆选清单时按此挑。偶尔外借导致某次打不满,接受(现实中那件确实看不到)。打卡规则不为在不在展做任何特殊处理。
9. **打满之后**(10-27 定):本轮停在「本轮已完成 ✓」,勋章已发;同一轮里再拍必看作品不开新一轮,仍按第 6 条——距上次打卡超过 30 天,下次来才从 0 开始。(讨论过「跟着门票走:开始用新票即开新一轮」,用户认为太复杂,维持 30 天。)
10. **勋章落表**(10-27 定):打满那一刻就记一条(谁、哪个馆、完成时间、件数),之后清单怎么改都不影响已发的勋章。(我的决定)拿到勋章后再删这一轮的足迹,**勋章不收回**,只影响当前轮进度。
11. **展厅号**(10-27 定):官网能取到展厅号的馆就标,取不到的不标;这条写进契约「上新馆」配方,以后每个新馆照做。
12. **呈现 = 护照页**(10-27 看样稿定):不做成第二个藏品列表(藏品页按热度排,前排几乎就是必看)。整页像护照内页,每件一个圆章位;打满后整页盖一枚完成大章且**一直盖着**;勋章画成**圆形奖章**(和大章同一图案);拍照命中时讲解页顶部只出几秒的临时提示,**点了也不跳**。

## 三、不做

- 路线规划、馆内地图(展厅号要做,见第五节第 5 条;但不画地图、不算路线)
- 「是否在展」判断与监测(见第二节第 8 条)
- 排行榜、积分、跨馆勋章墙
- 把老识别记录补算成打卡
- 打卡单独计费或免费

**反目标**(做了也算失败):打卡让识别变慢或改变扣费;老版本 App 因新字段崩溃或行为改变。

## 四、约束

- **契约只做加法**(项目最高优先级):新端点、新可选参数、新可空列;老 App 不受影响。Flutter 解析新字段一律 `as T? ?? 默认值`。
- 清单真相源仍是 `museums.yaml` 的 `must_see:`(`app/services/must_see.py` 的 `MUST_SEE`),改清单只部署后端。
- 打卡判据复用足迹的判据 `history.py::_footprint_qid`(确认过的 qid,或直判 `match` 的 top_qid,且不在 `rejected_qids` 里),不另写一套。
- 隐身馆(仅 can_preview 可见)沿用现有可见性规则。
- 十语文案;字号各语言一致,不用 FittedBox 缩字(见 i18n 规则),韩语沿用现有 word joiner 写法。
- 前端改动随下一个包(V75 起)。

## 五、怎么做(已定部分)

### 1. 识别请求带上「拍照/相册」

- `POST /api/v1/recognize` 加可选查询参数 `capture`:`camera` | `gallery`。缺省 = 未知。(App 相机页现在一律走全局端点;馆内端点 `/museums/{slug}/recognize` 同样加上,保持两端一致。)
- `recognition_events` 加可空列 `capture`(迁移)。老 App 的记录为 NULL,**NULL 不算打卡**。
- App 相机页:快门拍的传 `camera`,相册/最近照片选的传 `gallery`(相机页已能区分:`_lastShotLive` 只有快门为 true)。
- (我的决定)认不出作品时引导拍**说明牌**(`mode=label`)那张也是快门拍的,同样传 `camera`、同样算打卡:人在现场、照常扣费,符合「现场拍照识别成功」。

### 2. 什么算一次打卡

一条 `recognition_events` 记录同时满足:
- `user_id` = 当前用户(匿名不算);
- `capture = 'camera'`;
- `_footprint_qid(ev)` 有值,且这个 qid 在该馆的必看清单里;
- **`confirm_source` 不是 `search`**:拍了没认出、在选择页**搜到**再确认的不算(那条路不扣费,也不是识别成功;审查发现足迹判据本身不看 `confirm_source`,所以打卡要在足迹判据外再加这一层,足迹本身不变);
- 打卡时间取这条记录的 `created_at`(候选确认的也用原识别记录的时间)。

同一件作品一轮里打多次只算一次。

### 3. 轮与勋章

**轮(读的时候算)**:对某用户某馆,把所有打卡按时间排序;相邻两次间隔 **> 30 天**处切开,得到若干轮。
- **当前轮**:最后一次打卡距今 ≤ 30 天的那一轮;否则当前没有进行中的轮(进度 0/N)。
- 当前轮内打卡过的必看件覆盖了**当前清单的全部作品** → 本轮已完成。

**勋章(落表)**:新表 `must_see_medals`(user_id、museum_slug、completed_at、count、created_at)。
- 何时写:读 `must-see` 端点算出「当前轮已完成」、且该用户该馆**没有 `completed_at ≥ 当前轮开始时间` 的勋章**时,插一条;`completed_at` = 补齐最后一件的那次打卡时间,`count` = 当时清单件数。不改识别流程(反目标:打卡不能让识别变慢)。App 识别命中后本来就会刷新必看进度,所以写入时刻就是用户看到「打满」的那一刻。
- 已写的勋章永不随清单变化、删足迹而改动。删账号时随用户数据一并删除(沿用现有删账号路径)。
- 「本轮已完成」状态看当前轮进度;一轮里已有勋章就不再发第二枚(上面的判据保证)。

### 4. 新端点

`GET /api/v1/museums/{slug}/must-see`(令牌可选):
- 清单:按 yaml 顺序,每件给 `qid`、标题、作者、缩略图(与馆藏列表同口径、同语言回退规则,字段恒非 null),以及可空的 `location`(`wing`、`level`、`room`,见第 5 条);
- 带令牌时再给:当前轮已打卡的 qid 及各自打卡时间、当前轮开始时间、本轮是否已完成、勋章列表(每枚:完成时间、件数,新的在前);
- 不带令牌:只给清单,进度为空。
- 馆不存在/隐身且无权限 → 404;馆没有清单 → 空清单。

馆列表 `GET /api/v1/museums` 每项加字段 `must_see_count`(加法)。App 启动后馆列表已在缓存里(`museumsListProvider`),进馆页时**同步**读它决定是否显示「必看」标签页、是否设为默认,标签栏第一帧就对,不会跳(馆详情是异步拉的,放在详情里标签会先按「没有必看」画出来再变)。馆列表还没拿到时(极少,如深链冷启动)按没有必看处理。

### 5. 展厅号

- **存哪**:`museums.yaml` 的 `must_see:` 每项可写成 `{qid, wing?, level?, room?}`(老写法纯 qid 字符串继续认,= 无展厅号)。`wing` = 官方侧翼名原文(如 `Denon`,专名不翻译),`level` = 整数楼层(0 = 地面层,-2 = 地下二层),`room` = 厅号字符串。跟着部署上线,**不直写 prod 库**;刷新 = 一个改 yaml 的 PR,由用户合。
- **从哪取**:每馆一个取数脚本(`tools/` 下),只读官网、输出 yaml 片段供人工贴入:卢浮宫 = 官方 `collections.louvre.fr/ark:/53355/cl{P9394}.json` 的 `room`;橘园 = 作品页「Niveau / Salle」;小皇宫 = 巴黎博物馆集团藏品库作品页「Exposé」;奥赛官网拒绝程序访问(403)→ 不标。脚本请求要克制(逐件、间隔 ≥1s、不重试轰炸)。
- **怎么显示**:App 按语言拼(如中文「Denon · 1 层 · 711 厅」),缺哪个字段就不显示哪段;全无则不显示位置。
- **写进契约**:`docs/architecture/museum-api-contract.md` 的「上新馆」配方加一条:选必看 = 常年在展的镇馆之宝 + 逐件可识别检查;官网能取展厅号就取,取不到不标。
- 刷新时机:重审清单时顺带刷新;镇馆之宝很少换厅,不设定时任务。

### 6. App(护照页,样稿见 `2026-10-27-must-see-mockups/`:passport-v2b(三个时刻)、medal-styles(B 圆形奖章被选中)、must-see-layout(A/B/C 三选一,选 C))

- 馆页顶层标签:封面 / **必看** / 藏品;`must_see_count > 0` 时显示「必看」并默认选中,否则不显示、默认「藏品」(现有 `_MuseumTopTabBar` 已预留扩展位)。
- **必看页 = 护照内页**:标题「{馆名} · 必看」、副标题「已盖 X / N 枚章 · 本轮始于 {日期}」;三列圆章位,按 yaml 顺序排;有展厅号的按 (wing, level) 分组、组间用虚线分隔并写组名,无展厅号的件归最后一组「暂无展厅信息」;整馆都没有展厅号则不分组。
  - 未打卡:虚线圆圈 + 序号 + 标题(弱化色)+ 厅号;
  - 已打卡:圆形作品图、双线赤陶描边、略旋转,底部小签写打卡日期(如 10·27);
  - 点任一章位进该件讲解页。
- **打满**:护照上方一行「本轮已完成 ✓」,整页中央斜盖一枚完成大章(「必看完成 · 12/12 · {馆名} · {日期}」),**一直盖着**直到下一轮开始;下方「分享这一页」按钮。
- **我的勋章**:页底列出该馆全部勋章,每枚画成缩小的完成大章(圆形,写 12/12 和年月);没有勋章就不显示这一块。
- **拍照命中**:识别命中一件必看作品、进讲解页时,顶部浮出临时提示(小圆章 + 「盖章!必看 X/N」+ 展厅号),几秒后自动收起,**点了也不跳**、不打断讲解播放。补齐最后一件时提示改为「必看完成 N/N」,同样不跳;完成大章在用户下次打开必看页时看到。
- 进度在识别成功(直判命中,或候选确认)后刷新;必看页每次显示时也拉一次最新进度。
- 用 App 现有暖纸令牌(`GmColors`)与字体,亮暗双主题都要成立。

### 7. 上线前重审清单

现有四馆清单(卢浮 12、奥赛 23、小皇宫 7、橘园 8)按第二节第 8 条「常年在展的镇馆之宝」重审,同时做可识别性检查。可参考卢浮宫官方 JSON 的 `exhibition`(外借史)、Wikidata 的展览史;重审后的清单(连同取到的展厅号)交用户确认再改 `museums.yaml`;yaml 内顺序按馆内大致动线排(例:奥赛的梵高自画像外借频繁,需评估)。

## 六、留给实现者决定

- 打卡提示的进度数字从哪来:识别响应加一个加法字段,或识别后重新拉 `must-see` 端点;只要提示里的数字和必看页一致即可。
- 分享内容(文字 + 馆链接即可;做分享图要复用现有分享图的绘制方式)。
- 轮计算/勋章写入放在哪个服务模块、查询怎么写(一个用户在一个馆的打卡量很小,按用户+馆取出来在 Python 里切轮即可);勋章写入要防并发重复(同一用户同时两次请求)。
- 各语言的位置拼法(楼层叫法等),以及临时提示的停留秒数。
- 必看页的空态、加载态、失败重试,沿用馆页现有写法。

## 七、怎么算做成了

- 后端测试:`capture` 缺省/`gallery`/`camera` 三种只有 `camera` 算;搜索确认(`confirm_source=search`)不算;被否定(`rejected_qids`)的不算;删足迹后不计进度、但已发勋章不收回;同一轮只发一枚勋章(重复请求/并发不重复发);清单改动不影响已发勋章;yaml 新旧两种写法都认;30 天边界(恰好 30 天仍同轮、超过即新轮);打满出勋章、清单外作品不影响;匿名只给清单;隐身馆 404;老 App 不带 `capture` 的识别照常工作。
- 前端测试:有清单的馆默认「必看」、没有的不显示;章位按接口渲染、按位置分组(含「暂无展厅信息」组与整馆无展厅号不分组);打满时大章常驻;临时提示点了不跳转;新字段缺失不崩;十语布局扫描通过。
- 真机:在馆里拍一件必看作品 → 讲解页顶部提示「盖章!必看 1/N」并自动消失,必看页对应章位盖上;相册上传同一件不打勾。
