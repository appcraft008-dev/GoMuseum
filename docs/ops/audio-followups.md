# 音频待办台账（缺口 + 待人工校验）

**这张表是干什么的**：音频跑批会稳定产出两类"不该当场处理"的东西 ——
三次未过闸的**缺口**、和过了闸但机器判不了的**疑点**。
逐条追要么打断跑批节奏、要么被忘掉，所以统一记在这里，**攒够一批再一次性处理**。

**为什么不当场修**：契约「音频批量生产与灌入」⑬ 允许诚实缺口，
⑭ 记了重试两轮为限（救回率 5/8 → 1/2 → 0/2）。
当场重试的期望收益极低，而攒批处理能看出**模式**——
单条看是"这句念错了"，攒二十条才看得出"英语短问答锐度系统性超标"。

## 处理触发条件

| 类型 | 攒到多少动手 | 处理方式 |
| --- | --- | --- |
| 缺口 | 20 条，或某一语言占比 >5% | 一次性重跑；若集中在某语言 → 先动种子，不是加流程（契约 ⑭） |
| 待人工校验 | 15 条，或涉及已发布 TOP20 作品 | 集中试听一轮，判"真念错 / ASR 噪声"，前者重跑后者销账 |

## 记录纪律

- **一条一行，写清证据**，不要只写"有问题"。机器测出来的数字（锐度/一致性/真错率）原样抄进来——
  坍缩成"质量不好"之后，没人能倒推它错在哪，包括写它的人。
- 缺口**不要偷偷补**：手工 UPDATE 不走管线、不过闸（见契约 ⑯ 一类的教训）。销账走重跑。
- 处理完把行**移到"已销账"**并写结论，不要直接删——删掉就丢了"这条路走不通"的证据。

## 附：判读这张表时的已知陷阱

- **按分数挑样本会得出反向结论**（2026-09-09 繁体重灌实测）。要判"这批质量如何"，
  必须有**随机对照组**；只看最低分那几条，测出来的是分布尾巴，不是分布。
- **一致性分数分辨不了"同音选错"与"真念错"**，用 `tools/tts/reading_check.py`（读音级）。
- **读音比对有已知盲点**，会把念对的记成真错，统计时要剔除：
  阿拉伯数字↔汉字数字（「17」→「十七」是**念对了**）、opencc 折不掉的异体字（「着」→「著」）、
  片假名外来词拆分。
