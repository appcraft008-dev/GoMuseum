# 声音种子（永久固定，禁止修改／重新编码）

`SEED_zh.wav` 与 `SEED_en.wav` 是**全部 10 种语言音频的音色来源**。所有生产音频
都由这两条之一克隆而来。

## 哪条种子管哪些语言

代码里的真相源是 `tools/tts/run_batch.py` 的 `SEED_OF`；这里留一份**独立的底**，
因为代码会重构、会搬家，而这两个 wav 不可再生。**两者不一致时以代码为准，
但必须回头查清是谁改了、为什么。**

| 种子              | 语言                       | 依据                                                                                                                                                                                          |
| ----------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`SEED_zh.wav`** | zh、fr、de、es、it、pl、ko | 拼音文字用 zh 种子音质最优（§二：es 用自己的种子锐度 326%，用 zh 种子 92%）                                                                                                                   |
|                   | **zh-hant**                | 2026-08-31 由 `SEED_en` 改正而来。原判据「zh 念繁体一致性仅 0.58」出自**还坏着的打分函数**；修好后重测 ZH 0.951 / EN 0.913、锐度 144 / 189，三项全胜                                          |
| **`SEED_en.wav`** | en                         | 用自己的种子                                                                                                                                                                                  |
|                   | **ja**                     | **发音准确度优先**：ZH 种子浊音念错（「じっくり」→「つっくり」）。2026-09-07 用修好的浊音归一化重测 **EN 0.983 / ZH 0.970**，方向与幅度均未变，决策维持。ZH 锐度更好（99 vs 151）但让位于发音 |

> ⚠️ 「用该语言自己的种子念该语言」通常是**最差**组合（§二），
> 但 zh 是反例（它用 `SEED_zh` 且全语言最干净）—— 别把它当定律。

## 还有多少音频要靠这两个文件生成

截至 2026-09-07（prod 实测）：

| 种子          | 语言数 | 已有音频 | 已发布段落 | 完成度   |
| ------------- | ------ | -------- | ---------- | -------- |
| `SEED_zh.wav` | 8      | 563      | 21,234     | 2.7%     |
| `SEED_en.wav` | 2      | 137      | 5,313      | 2.6%     |
| **合计**      | 10     | **700**  | **26,547** | **2.6%** |

**97% 的音频还没生成，全部依赖这两个文件。** 这不是历史存档，是在用的生产资产。

## 为什么这两个文件必须存在仓库里

不变量①「同语言音色一致」要求某语言的**全部**音频克隆自同一个种子。
一旦这两个文件丢失：

- 已发布的约 700 条音频**无法再匹配** —— 新设计的种子是另一把嗓子；
- 要恢复一致，只能把该语言**全部**音频重灌一遍，而用户会听到音色突变。

它们不可再生：种子由 VoxCPM2 设计模式随机抽样产生（见配方 §五），
同样的描述词再抽一次也是**另一个人**。

## ⚠️ 种子不是用来听的 —— 它是原料，不是成品

**种子的声音和成品的声音不是同一把嗓子。** 直接播 `SEED_*.wav` 去判断音色好坏
会得出错误结论。

|          | `SEED_*.wav`                 | `FINAL_*.mp3`（成品）          |
| -------- | ---------------------------- | ------------------------------ |
| 生成方式 | 设计模式：由文字描述直接生成 | 克隆模式：以种子为参考音再生成 |
| 角色     | 音色的**来源**               | 用这个来源**做出来的东西**     |

克隆是**重建**而非复制：模型保留「人格特征」但不照抄细节。同一条英语正文实测：

|                                | 锐度  | F0      | 亮度 |
| ------------------------------ | ----- | ------- | ---- |
| `SEED_en.wav`                  | 196.6 | **175** | 2594 |
| `FINAL_en.mp3`（它的克隆成品） | 183.3 | **159** | 2165 |

音高低了 16 Hz、亮度掉了 17%。（时长差是 atempo 对齐 tts-1 基准所致，
atempo 只伸缩时间不改音高，实测 F0 变化 ≤2Hz，不是音高差的来源。）

**顺带排除压缩这个嫌疑**：把 `SEED_en.wav` 按同样 160k 编成 mp3 后，
锐度 196.6→196.7、F0 175→175、亮度 2594→2594，**四项数值不动**。
wav 与 mp3 听起来不同，原因不在编码。

> 🔴 **这条曾直接坑掉一次实验**（配方 §四「英语种子重选实验」）：
> 按「种子锐度最低」筛出的候选 r01（种子 93.7，全场最干净），
> 克隆成品 F0 掉到 142，用户一听就是「完全换了个人」，排名最后。
> **要评估效果，必须听克隆成品，不能听种子。**

## 禁止事项

- **禁止重新编码**（含无损转码）。喂给模型的必须是当初那个字节流。
  校验用 `seeds/CHECKSUMS.txt`。
- **禁止"优化"**（降噪、EQ、重采样）。配方 §六 记着这些全部试过且有害。
- **替换不是文件操作，是产品决策。** 换种子必须连带把该语言**全部**已发布音频
  重灌（不变量①），否则用户会在同一个 App 里听到两把嗓子。
  2026-09-07 走过一次这条路并否决（配方 §四），但那是针对当时的候选，
  **不是永久封路**。
  ⏳ **成本随已生成音频量上升，要换趁早**：当前 en+ja 已生成 137 条，
  灌完则是 5,313 条。越晚越会从「技术选择」变成「不可能选项」。

## 来源

| 文件          | 来源抽样    | 锐度      | F0  | HNR  |
| ------------- | ----------- | --------- | --- | ---- |
| `SEED_zh.wav` | `v10_zh_d1` | **167.8** | 179 | 16.8 |
| `SEED_en.wav` | `v10_en_d1` | **196.6** | 175 | 16.4 |

锐度为**生产口径**（`run_batch.py` 的 `qc()`：`sr=22050 / duration=60 /
n_fft=2048 / 幅度谱`）。`manifest.json` 记的 168 / 199 是同一口径的原始记录，
两者一致。

> ⚠️ **量锐度必须用生产那个函数，别另写。** 曾用临时量法
> （`sr=None` 全长 + 复数谱）测同一条 `SEED_en.wav` 得 132.1，与生产口径
> 差 64.5 点，并据此和成品分数相减，凭空造出一个不存在的「偏移」现象。
> 详见配方 §四「⚠️ 同一指标必须同一口径」。
